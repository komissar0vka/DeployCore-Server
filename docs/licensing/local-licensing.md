# Локальное лицензирование DeployCore 1.0

## Устройства и квота

Миграция `0008_local_licensing` отмечает существующие доступные устройства как `managed`, исторически удалённые как `retired`. UUID, инвентарь и журнал не переписываются. В разделе «Лицензия» видны лимит и число управляемых устройств. Free предоставляет пять мест.

Новый UUID занимает место в той же транзакции, в которой потребляется регистрационный токен. Повтор ранее принятой регистрации и адресное восстановление управляемого устройства сохраняют прежнее место. Отзыв ключа и потеря связи на квоту не влияют. При превышении лимита существующие устройства продолжают работу, новый UUID и возобновление управления отклоняются.

Super Admin может снять устройство с управления после завершения или сверки развёртываний. Незапущенные выдачи отменяются. Ключ и токены восстановления отзываются, UUID, инвентарь и история сохраняются. Возобновление занимает свободное место. Для подключения после возобновления нужен новый токен восстановления. Прежний маршрут удаления устройства остаётся отдельной операцией с очисткой инвентаря.

## Подписанная выдача

UUID экземпляра создаётся миграцией и отображается в панели. Выдача привязывается к этому UUID и отпечатку локального открытого ключа. Для проверки серверу предоставляется локальный файл доверия с двумя свойствами:

- `instance_public_key` — открытый ключ Ed25519 экземпляра, 32 байта в base64url без дополнения.
- `issuer_keys` — объект, где ключи соответствуют `kid` издателей, а значения содержат их 32-байтовые открытые ключи в том же формате.

В Compose путь внутри контейнера задаётся `DEPLOYCORE_LICENSE_TRUST`. Для коммерческой выдачи используйте отдельный mount файла только для чтения. Секретные ключи издателя или экземпляра не нужны серверу для импорта.

Super Admin загружает подписанный JSON через раздел «Лицензия». Сервер проверяет Ed25519, привязку, сроки и номер выдачи, затем атомарно сохраняет конверт и водяной знак и фиксирует событие аудита. При окончании подписанного льготного периода или при недоступности проверки действует лимит Free. Принятый документ и водяной знак сохраняются. Дополнительные поля возможностей проверяются как часть подписанного документа. Действующая локальная интеграция применяет лимит устройств.

## Открытые проверки

Отдельной работы требуют доставка подписанных отзывов и ротация доверия, проверки восстановления резервной копии с ключами, стендовая приёмка восстановления Windows Agent после снятия и возобновления управления. [План Windows-приёмки](../releases/1.0-stage-1.md)

## Результаты проверки

- 58 тестов pytest, Go test и vet, Windows amd64 cross-build, TypeScript/Vite, сверка OpenAPI и Chromium с тестовым API.
- Отдельный прогон PostgreSQL подтвердил обновление с `0007`, сохранность инвентаря, статусы старых UUID и неизменность UUID экземпляра при повторном запуске миграций.
- Изолированный Compose принял пять из шести конкурентных регистраций Free. Проверены отзыв ключа, повторная регистрация, освобождение места, сохранение ПО, запрет снятия при незавершённом развёртывании, восстановление управления, подпись, защита от старой выдачи, RBAC, CSRF и переход на Free при потере доверия.
