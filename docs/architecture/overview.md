# Архитектура DeployCore

DeployCore разворачивается экземпляром на организацию. Администратор и Windows Service обращаются к Nginx по HTTPS. Nginx отдаёт сборку React и проксирует REST API FastAPI. PostgreSQL 16 доступен серверу по внутренней сети Compose и хранит состояние в выделенном томе.

| Путь | Назначение |
| --- | --- |
| `apps/server` | FastAPI, слой API, прикладные сценарии и адаптеры хранения |
| `apps/web` | React, TypeScript, Tailwind CSS, shadcn/ui и TanStack Query |
| `apps/agent` | Go Windows Service с исходящими HTTPS-соединениями |
| `packages/api-contract` | Версионируемые схемы OpenAPI |
| `packages/package-manifests` | Версионируемые схемы манифестов, этап 4 |
| `deploy` | Compose, Nginx, TLS и эксплуатационные проверки |

Прикладные сценарии используют интерфейсы к БД и файловому хранилищу. HTTP-слой проверяет данные и полномочия, адаптеры отвечают за сохранение и внешние операции. Этап 2 добавляет первый запуск, серверные сессии, настройку экземпляра, управление ролями и аудит. Nginx раздаёт интерфейс Swagger и Windows Agent из локальной сборки. Этап 3 добавляет регистрацию, heartbeat, инвентарь и управление устройствами.

Агент будет получать задания по исходящему HTTPS независимо от членства в домене. Каталог будет хранить метаданные в БД и файлы в отдельном локальном хранилище по SHA-256. Очередь PostgreSQL будет выдавать задания с ограниченной по времени арендой. Утерянную связь обработают истечение аренды и сверка результата перед повтором операции.


В этапе C очередь выдаёт подписанный и утверждённый артефакт только для активной попытки конкретного устройства. Перед созданием процесса агент фиксирует намерение в DPAPI, а сервер подтверждает старт в PostgreSQL. При неопределённом исходе дальнейшие задания на устройстве блокируются до ручной сверки.
