# REST API

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/health/live` | Проверка процесса FastAPI |
| `GET /api/health/ready` | Проверка подключения к PostgreSQL. При сбое возвращает 503 |
| `GET /api/openapi.json`, `GET /api/docs` | Схема OpenAPI и локальный Swagger UI |
| `GET /api/v1/setup` | Публичное состояние первоначальной настройки и язык интерфейса |
| `POST /api/v1/setup` | Одноразовое создание экземпляра и первого Super Admin |
| `POST /api/v1/auth/login` | Вход, выдача cookie и CSRF-токена. При превышении лимита возвращает 429 |
| `GET /api/v1/auth/session` | Текущий пользователь, CSRF-токен и ближайший срок действия сессии |
| `POST /api/v1/auth/logout` | Отзыв серверной сессии и удаление cookie |
| `GET /api/v1/settings` | Чтение настроек всеми авторизованными ролями |
| `PUT /api/v1/settings` | Изменение настроек ролью Super Admin |
| `GET /api/v1/users`, `POST /api/v1/users` | Просмотр и создание пользователей ролью Super Admin |
| `PATCH /api/v1/users/{user_id}/role` | Изменение роли пользователя ролью Super Admin |
| `GET /api/v1/audit` | Последние 100 событий аудита для Super Admin |

Для изменяющих запросов нужны заголовки `Origin` со значением публичного HTTPS origin и `X-DeployCore-Request: 1`. Авторизованные изменяющие запросы также передают токен из ответа входа или чтения сессии в `X-CSRF-Token`. Защищённые ответы и ошибки прикладных маршрутов используют `Cache-Control: no-store`. При успешном авторизованном запросе `X-DeployCore-Session-Expires` содержит обновлённый срок сессии.

Swagger раздаёт JavaScript, CSS и значок из локальных файлов. Для интерактивных изменяющих вызовов используйте веб-панель или HTTP-клиент с указанными заголовками. FastAPI служит источником схемы в `packages/api-contract`.

## Устройства и Windows Agent

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/v1/devices` | Поиск по имени, FQDN и IP, статус, пагинация, сортировка |
| `GET /api/v1/devices/summary` | Статусы, версии агентов, последние события и ошибки |
| `GET /api/v1/devices/{device_id}` | Метаданные, последний снимок, программы и последние 100 событий |
| `DELETE /api/v1/devices/{device_id}/agent` | Отзыв ключа агента и ожидающих токенов восстановления |
| `DELETE /api/v1/devices/{device_id}` | Удаление из списка, очистка инвентаря, сохранение события и аудита |
| `GET /api/v1/enrollment-tokens` | Метаданные ранее выданных токенов |
| `POST /api/v1/enrollment-tokens` | Выдача токена. Секрет присутствует только в этом ответе |
| `DELETE /api/v1/enrollment-tokens/{token_id}` | Отзыв токена |
| `POST /api/v1/agent/enroll` | Регистрация или замена ключа по enrollment-токену |
| `POST /api/v1/agent/{device_id}/heartbeat` | Актуальные сведения и серверный интервал |
| `PUT /api/v1/agent/{device_id}/inventory` | Замена снимка устройства и списка программ |
| `POST /api/v1/agent/{device_id}/issues` | Сообщение об ошибке инвентаризации. Повторы одного типа от машины ограничены одним событием в час |

Чтение карточек доступно всем авторизованным ролям. Управление устройствами и токенами доступно Super Admin и Administrator и требует CSRF. Машинные маршруты используют HTTPS и JSON. Heartbeat, инвентарь и сообщения об ошибках используют отдельный Bearer-ключ агента. Тело машинного запроса ограничено 2 MiB, снимок содержит до 2 000 программ. Сервер вычисляет статус по принятому heartbeat и своему времени, при пороге в три интервала или 180 секунд, если это больше. Отозванный ключ переводит устройство в офлайн сразу.


Список устройств принимает `sort=hostname|status|os|agent|last_seen` и `direction=asc|desc`. По умолчанию сохраняется порядок по имени и ID. Сортировка применяется перед пагинацией.

## Каталог программ

Список, карточка, версии, бинарная загрузка, скачивание и утверждение описаны в [контракте этапа A](../releases/0.5.0-stage-a.md#api). Действующие маршруты Windows Agent сохранены.

Super Admin может утвердить загруженный MSI/EXE с неподтверждённой подписью через `POST /api/v1/packages/{package_id}/versions/{version_id}/approve-manual`. В теле передаётся `sha256` проверенной копии файла. Сервер сверяет значение с каталогом и хранимыми байтами. Каталог показывает `approval_kind: manual`, а статус Authenticode остаётся `unverified`. Аудит сохраняет администратора, время и SHA-256. Изменение или удаление записи установщика сбрасывает утверждение. Замена установщика через каталог выполняется созданием новой версии. Задания привязаны к SHA-256, а агент проверяет байты перед запуском.

### Обнаружение и проверка после перезагрузки

Одиночные правила сохраняют формат. Группа содержит `kind: all|any`, `schema_version: 1` и от 2 до 8 одиночных правил в `rules`. Группы и новые машинные запросы требуют Agent 0.3.5+ и заголовка `X-DeployCore-Capabilities: execute_v1, detection_v1`.

| Маршрут относительно `/api/v1` | Операция |
| --- | --- |
| `POST /detection-previews` | Создать предпросмотр для `device_id` и `version_id` |
| `GET /detection-previews/{preview_id}` | Прочитать собственный запрос. Super Admin может читать все запросы |
| `POST /agent/{device_id}/detection-previews/poll` | Получить одно правило для текущего устройства |
| `POST /agent/{device_id}/detection-previews/{preview_id}/result` | Вернуть `observation` |
| `POST /agent/{device_id}/jobs/{target_id}/reboot-result` | Передать `attempt_id` и `detection`. Значение `null` сообщает об истечении локального срока |

Для предпросмотра требуется Administrator или Super Admin, при создании действует защита CSRF. Запрос активен две минуты. За это окно разрешён один запрос на устройство и до пяти на оператора. Машинные маршруты используют Bearer-ключ соответствующего устройства.

В `jobs/.../result` Agent 0.3.5 может передать `detection`, `process_started` и `reboot_pending: true`. В последнем случае состояние цели становится `awaiting_reboot`. Завершающая проверка дополняет текущую попытку полями `reboot_detection` и `reboot_finished_at`. Код исходного процесса сохраняется.

### Фильтры панели

- `GET /deployments` принимает `q`, `scope=all|active|problem`, `operation`, `device_id`, `direction`, `offset` и `limit`. `total` учитывает фильтры, `active` и `problem` относятся ко всему экземпляру. Проблемные задания включают ошибки, неизвестные исходы и просроченные подтверждённые попытки или проверки после перезагрузки.
- `GET /deployments/{job_id}/events` принимает `target_id` и курсор `before`, события попыток содержат `attempt_number`.
- `GET /devices` принимает статус `revoked` и точное значение `agent_version`. `GET /packages` поддерживает сортировку по `name` и `publisher`, направление задаёт `direction`.

## Локальная лицензия и управление устройствами

- `GET /api/v1/licenses` возвращает UUID экземпляра, редакцию, лимит, количество управляемых устройств и состояние выдачи. Запрос доступен ролям с правом чтения.
- `POST /api/v1/licenses/import` принимает конверт версии 1 размером до 24 КиБ с проверкой Origin и CSRF. Импорт доступен Super Admin.
- `POST /api/v1/devices/{device_id}/retire` и `/resume` требуют Super Admin и CSRF. Фильтр `management_state=managed|retired` доступен в списке устройств.
- Регистрация нового UUID и возобновление управления возвращают `409 license_limit_reached`, если мест нет. Восстановление управляемого UUID не занимает нового места.
