# DeployCore Changelog

## Server 1.0.0-beta.2

- Интерактивная установка на Ubuntu и отдельный клиентский релизный архив.
- Подключение к Cloud с доказательством владения ключом, проверкой Ed25519 и офлайн-политикой с льготным периодом 14 дней.
- Просмотр подписанных каналов Stable/Beta и локальный скрипт обновления с резервированием и восстановлением БД.
- Приёмка Windows и установка на чистой Ubuntu 22.04 остаются открытыми.

## Готовый MSI Windows Agent 0.3.7

- Мастер сервера сохраняет IP или DNS-адрес для агентов. Авторизованный оператор может скачать MSI с сохранённым адресом и ограниченным токеном регистрации.
- Готовый MSI регистрирует службу через Windows Installer. Агент переносит параметры первичной регистрации в DPAPI. Общий MSI с ручной настройкой остаётся доступен.

## 1.0 · локальная интеграция этапа 3

- Миграция `0008_local_licensing` добавляет состояние управления, постоянный UUID экземпляра и хранение принятой выдачи.
- Регистрация, освобождение и повторное занятие места сериализуются в PostgreSQL. Free допускает пять управляемых UUID. Снятие с управления сохраняет историю и инвентарь.
- Добавлены локальный импорт Ed25519 с аудитом, переход на Free при недоступности выдачи и рабочий экран лицензии с лимитом и состоянием.
- Cloud остаётся отдельным контрактом. Приёмка на реальной Windows остаётся открытой.

## 1.0 · фундамент этапа 3

- Модель Free учитывает до пяти управляемых UUID. Явное снятие с управления освобождает место, повторная регистрация управляемого UUID использует прежнее место.
- Добавлены локальная проверка Ed25519 с привязкой к экземпляру, сроками и защитой от старых выдач, тесты с временными ключами и OpenAPI будущего Cloud.
- Правила подготовлены на уровне доменной модели. Подключение к БД и регистрации, развёртывание Cloud и эксплуатационная проверка относятся к следующим этапам.

## 1.0 · этап 2, интерфейс

- Дашборд показывает активные и проблемные развёртывания, здоровье сервера и состояние парка. Из сводки можно открыть задание или отфильтровать агентов по версии.
- Добавлены мониторинг Windows Agent, журнал развёртывания с фильтром по компьютеру и номером попытки, фильтры и сортировка очереди и каталога.
- Карточка компьютера показывает историю развёртываний и разбивает список ПО на страницы. Профиль переключает RU/EN и тему. Пункты навигации для будущих модулей убраны.

## 1.0 · стабилизация перед этапом 2

- При удалении устройства незапущенные задания закрываются, запущенные сохраняются с неизвестным исходом. Создание и удаление сериализуются блокировкой устройства.
- Agent 0.3.6 освобождает локальный журнал при явном закрытии попытки сервером. Ошибка конфликта оставляет журнал для диагностики. Прежний протокол агентов сохранён.
- Утверждение Authenticode повторно сверяет SHA-256 хранимых байтов. Исчезновение артефакта при подготовке выдачи возвращает ошибку доступности хранилища.
- Прошли 43 теста pytest, Go test и vet, Windows amd64 cross-build, TypeScript/Vite и изолированный Compose smoke с проверкой гонки удаления.
- Приёмка на реальной Windows остаётся открытой. [Сценарии приёмки](docs/releases/1.0-stage-1.md).

## 1.0 · этап 1, надёжность исполнения

- Agent 0.3.5 различает `installed`, `not_installed` и `unknown`. Ошибки чтения реестра сохраняют неопределённость. Недоступность проверки и подтверждённое несовпадение показаны как отдельные причины.
- Добавлены составные правила `all` / `any`, предпросмотр на тестовом устройстве и отдельная проверка после перезагрузки. Журнал агента сохраняет ожидающую проверку и её результат между перезапусками.
- Миграция `0007_detection` сохраняет сведения о запуске и отдельные наблюдения. Agent 0.3.4 обслуживается по прежнему контракту с одиночными правилами.
- Прошли 38 тестов pytest, Go race и vet, кросс-сборка Windows, сборка веб-панели, сценарии Chromium и изолированный Compose. Приёмка на доменной и недоменной Windows остаётся открытой. Матрица проверки приведена в [отчёте этапа 1](docs/releases/1.0-stage-1.md).

## Windows Agent 0.3.2

- Исправлен запуск графического мастера через Windows PowerShell. HTTPS-адрес вводится в отдельное поле.
- Соглашение описывает права службы, инвентаризацию и передачу данных выбранному серверу. Для установки через мастер нужно подтвердить согласие.

## 0.3.1 — стабилизация и улучшение интерфейса

- EXE открывает мастер по двойному щелчку. MSI устанавливает мастер в меню «Пуск». Адрес и регистрационный токен задаются на компьютере.
- Установка и команда `check` проверяют доверие TLS, имя сервера и ожидаемый ответ readiness. Команды в панели копируются по отдельности.
- Дашборд показывает количество компьютеров по статусу, версии агентов, последние события и ошибки. Боковое меню адаптируется к ширине экрана. Добавлены пустые состояния.
- Инвентаризация показывает модель и производителя компьютера, метки и файловые системы томов, MAC-адреса и ранее доступные сведения о CPU, памяти, сети и ПО. Снимки 0.3.0 по-прежнему читаются.
- Добавлены инструкция GPO, сценарий приёмки и проверка Windows MSI, службы и TLS-протокола в CI. Схема PostgreSQL не менялась.
- Проверены 14 тестов FastAPI, Go с детектором гонок, go vet для Linux и Windows, сборка TypeScript/Vite, интерфейс в Chromium и запуск нового изолированного экземпляра Compose. EXE и MSI Windows x64 собраны. Проверены содержимое MSI и SHA-256. Приёмка мастера, установки и GPO на реальной Windows остаётся открытой.
