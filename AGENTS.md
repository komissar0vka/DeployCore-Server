# DeployCore

- Порядок и критерии этапов описаны в `docs/roadmap.md`. Завершайте проверку текущего этапа перед началом следующего.
- Обновляйте README и CHANGELOG по результатам каждого этапа. Отмечайте проверки, которые не удалось выполнить.
- Размещайте исходники DeployCore в `apps/` и `packages/`, инфраструктуру в `deploy/`.
- Используйте типизированные контракты, параметризованные запросы и миграции для изменений прикладной схемы.
- Не добавляйте в Git секреты, TLS-ключи, зависимости или сборочные артефакты.

## Актуальная точка продолжения DeployCore 1.0

- Начинайте с [состояния разработки](docs/releases/1.0-handoff.md). Последняя реализация `48c5017` добавляет готовый MSI Agent 0.3.7. Текущая вершина схемы `0008_local_licensing`.
- Последний известный порт рабочего DeployCore — `8444`. Исторические сведения ниже относятся к ранним версиям. Сохраняйте рабочий экземпляр, PostgreSQL, TLS, секреты, рабочие агенты и тома. FlipHunter, n8n и Xray не затрагивайте. Не выполняйте `git push`, глобальную очистку Docker, реальные задания установки либо публикацию Cloud или обновлений без отдельного согласования.
- Приёмка на реальной доменной и недоменной Windows остаётся открытой. Для готового MSI проверьте установку без ручного ввода, регистрацию, перезапуск и удаление службы. Остальные открытые проверки перечислены в документе состояния.

## Состояние проекта после v0.3.0

- Этап 1. Отдельный Compose-проект DeployCore с PostgreSQL 16, FastAPI, React и Nginx. HTTPS по умолчанию на порту 8443. Проверки liveness и readiness, локальный контракт OpenAPI и сквозной smoke-тест.
- Этап 2. Мастер первичной настройки, создание первого Super Admin в одной транзакции, Argon2id, серверные сессии и CSRF, ограничения входа, роли Super Admin, Administrator и Viewer, настройки и аудит. Swagger UI раздаётся локально. Первая миграция — `0001_system`.
- Этап 3. Windows Agent на Go, регистрационные токены с квотой, сроком и отзывом, стабильный UUID, отдельный ключ агента, защищённое состояние DPAPI, heartbeat, инвентаризация и восстановление ключа. Разделы «Компьютеры» и «Установка агента», миграция `0002_devices`, сборка Windows x64 с SHA256SUMS и build.json. Документация установки находится в `apps/agent/README.md`.
- Проверено для v0.3.0. Прошли 14 тестов Python, 4 теста Go, go vet для Linux и Windows, кросс-сборка Windows x64, проверка SHA-256, сборка Vite, изолированный Compose smoke-тест и браузерная проверка основных экранов.
- Приёмка Windows остаётся открытой. Нужен прогон на реальной Windows, включая перезапуск службы, нативный сбор инвентаря и работу на доменной машине. Workflow Windows подготовлен, его выполнение в GitHub Actions не подтверждено. MSI отложен. Рабочий экземпляр DeployCore в рамках этой разработки не обновлялся.
- Для продолжения используйте существующий DeployCore. FlipHunter и n8n запрещено останавливать, пересоздавать или изменять. Не выполняйте глобальную очистку Docker. Сохраняйте существующие секреты, параметры PostgreSQL, данные, TLS и порт 8443 DeployCore. Проверки запускайте в отдельном Compose-проекте с временными данными.
- Следующий этап по дорожной карте — каталог программ, локальное хранение установщиков и манифесты. Соблюдайте критерий проверки этапа 3 перед переходом. Подробности изменений и команды запуска находятся в README и CHANGELOG.

## Стабилизация v0.3.1

- Добавлены графический мастер EXE, MSI, проверка готовности HTTPS при установке, сводка по устройствам и расширенные снимки инвентаризации. Инструкция по GPO и сценарий приёмки находятся в `docs/windows-agent-rollout.md`.
- CI Windows проверяет MSI и жизненный цикл установленной службы с тестовым HTTPS-сервером. Приёмка мастера и GPO на реальной Windows требуется. Модуль установки программ остаётся за рамками v0.3.1.
