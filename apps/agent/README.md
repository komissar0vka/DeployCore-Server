# DeployCore Agent для Windows

Агент v0.3.4 предназначен для Windows 10/11 x64 и Windows Server x64 с Windows PowerShell 5.1, CIM и реестром Windows. Служба `DeployCoreAgent` запускается автоматически под LocalSystem. Журнал доступен в Windows Event Viewer → Windows Logs → Application, источник `DeployCoreAgent`.

## Установка

В панели откройте «Установка агента» и создайте токен с подходящим сроком и квотой. Скачайте `deploycore-agent.msi` и `SHA256SUMS`. Сравните SHA-256 с опубликованной контрольной суммой. Установите MSI, затем запустите **DeployCore Agent Setup** из меню «Пуск» и подтвердите UAC. Введите HTTPS-адрес с портом, если он нужен, и токен. Прочитайте соглашение и отметьте «Я принимаю соглашение об установке». Кнопка «Проверить HTTPS» доступна до принятия соглашения. Мастер проверяет TLS и готовность API перед созданием службы. Статус регистрации появится в разделе «Компьютеры». Скачанный отдельно EXE открывает тот же мастер при двойном щелчке.

Для консольной установки откройте PowerShell от имени администратора в каталоге EXE:

```powershell
$server = 'https://deploycore.example:8443'
.\deploycore-agent.exe check --server $server
[Net.NetworkCredential]::new('', (Read-Host 'Enrollment token' -AsSecureString)).Password | .\deploycore-agent.exe install --server $server
Get-Service DeployCoreAgent
```

Команда `install` автоматически выполняет ту же HTTPS-проверку. Поля MSI и аргументы команд предназначены для данных без секретов. Токен вводится в защищённое поле мастера или передаётся через stdin.

Для корпоративного CA установите корневой сертификат в доверенное хранилище локального компьютера или добавьте `--ca C:\PKI\root-ca.pem` к командам `install` и `check`. Проверка цепочки и DNS-имени остаётся обязательной. Токен читается из stdin, а его значение не передаётся в аргументах процесса. Проверьте результат в «Компьютерах».

## Перезапуск, восстановление и удаление

```powershell
Restart-Service DeployCoreAgent
.\deploycore-agent.exe uninstall
```

`uninstall` останавливает и удаляет службу. Состояние в `%ProgramFiles%\DeployCore\state.dpapi` сохраняется для переустановки с тем же адресом. Оно защищено машинным DPAPI и ACL каталога для LocalSystem и администраторов. Для вывода компьютера из управления отзовите ключ в панели или удалите устройство. Для новой идентичности после удаления службы и устройства удалите локальный `state.dpapi` и установите агент с новым обычным токеном.

Для замены ключа выдайте токен восстановления в карточке компьютера и передайте его установленному агенту через stdin.

```powershell
[Net.NetworkCredential]::new('', (Read-Host 'Recovery token' -AsSecureString)).Password | & "$env:ProgramFiles\DeployCore\deploycore-agent.exe" recover
```

При восстановлении на чистой Windows используйте `install --server $server --device-id <UUID>` с токеном восстановления и UUID из той же карточки. При просрочке или ошибке токена на машине, ещё не зарегистрированной сервером, вызовите `recover` с новым обычным токеном. Сервер заменяет ключ уже зарегистрированного устройства только по привязанному к нему токену восстановления.

Для обновления уже установленной службы остановите и удалите её командой `uninstall` старого или нового EXE, затем запустите `install --server $server` новой версией. Агент использует сохранённую регистрацию при том же адресе. В мастере оставьте токен пустым при повторной установке с сохранённым состоянием. Пакет MSI управляет файлами мастера в `%ProgramFiles%\DeployCore Agent`. Перед удалением MSI удалите службу отдельной командой, если хотите прекратить управление компьютером.

См. [массовое развёртывание через GPO и приёмку на Windows](../../docs/windows-agent-rollout.md).

## Инвентаризация и сборка

Heartbeat по умолчанию отправляется каждые 60 секунд. Инвентаризация отправляется после подключения и затем каждые шесть часов. CIM используется для производителя и модели компьютера, CPU, RAM, меток и файловых систем локальных дисков с буквами. Для сетевых интерфейсов собираются IP и MAC. Список программ берётся из uninstall-ключей реестра в 64- и 32-битных представлениях HKLM и загруженных пользовательских профилей. Офлайн-профили и приложения без подходящей записи реестра могут отсутствовать в снимке.

Из `apps/agent` на Linux с Go 1.25 и `wixl` выполните `go test ./...` и `./build.sh dist`. Compose и CI собирают EXE, MSI, `SHA256SUMS` и `build.json`. Пакеты этой сборки без подписи Authenticode. Для управляемого развертывания используйте утверждённый процесс подписи вашей организации.


## Очередь этапа B

Агент 0.3.3 проверяет транспорт заданий через действующий HTTPS. До ACK он сохраняет попытку в `deployment.dpapi`. После перезапуска повторяет незавершённый обмен с тем же ID. Установщики в этой сборке не запускаются. [Протокол и восстановление](../../docs/releases/0.5.0-stage-b.md#протокол).

## Обнаружение в Agent 0.3.5

Agent объявляет `detection_v1` вместе с `execute_v1`. Реестр обнаружения проверяется в обеих проекциях HKLM Uninstall. Недоступный подраздел или ошибка чтения возвращают `unknown`, если совпадение не найдено. MSI проверяется в контексте Windows Service LocalSystem.

При принятом коде 3010, 1641 или установленном флаге перезагрузки журнал DPAPI сохраняет правило, идентификатор загрузки и срок проверки. После смены идентификатора агент проверяет только метаданные и передаёт наблюдение текущей попытки. При аварийной остановке до сохранения кода процесса исход остаётся неизвестным для ручной сверки.
